# LiteArm VR Studio 操作手册

## 1. 软件简介与连接

> [!IMPORTANT]
> 机械臂运动具备一定惯性与力量。开始遥操前，必须确保机械臂工作范围内无人员驻留、无障碍物干涉，并让物理急停处在可及范围内。

### 1.1 这个上位机是什么

本版本的 LiteArm VR Studio 是 **VR 遥操控制台**。它不在控制回路上：手柄帧从 Pico 头显经 `litearm-vr-bridge` 进入遥操服务（metavr），由它解 IK 后下发跟随服务，跟随服务再驱动机械臂的 STM32 控制器。上位机只负责看这条链路，并提供开关：

```
Pico 头显 ──Wi-Fi──> litearm-vr-bridge :8765
                         │  zenoh
                         ├──> metavr 遥操（IK）──> 跟随服务 ──> STM32 ──CAN──> 电机
                         └──> 本上位机（状态、起停、急停、配置）
```

两个必须记住的推论：

- **上位机不在运动路径上。** 关闭上位机不会停止正在运行的遥操链路；要停请按 **停止遥操** 或物理急停。
- **机械臂串口是独占的。** 上位机打开串口读状态（电机负载、端口）；按 **开始遥操** 会把串口交给跟随服务，遥操停止后再拿回来。

上位机由**一个本地程序**（`litearm-vr-studio-daemon`）和**一个内嵌窗口**组成。本地程序只监听 `127.0.0.1`，界面走回环；本地程序通过 zenoh 与桥通信。

### 1.2 需要先跑起来的东西

| 组件 | 位置 | 默认 |
| :--- | :--- | :--- |
| `litearm-vr-bridge` | 控制主机 | 状态页 `ws://<控制主机>:8765`，头显连这里 |
| 遥操 + 跟随服务 | 由桥的受管进程拉起 | — |
| `litearm-vr-studio-daemon` | 控制主机 | zenoh 端点 `tcp/127.0.0.1:7447` |
| 头显 | Wi-Fi，指向桥 | `ws://<控制主机>:8765` |

本地程序默认连本机的 `tcp/127.0.0.1:7447`。桥在别的机器上时，用 `--vr-endpoint tcp/<host>:<port>` 启动本地程序——端点属于那台机器的配置，页面不会让操作员填。

### 1.3 安装与运行

下载对应平台的可执行文件，并用旁边的 `.sha256` 校验：

| 平台 | 文件 | 运行方式 |
| :--- | :--- | :--- |
| Ubuntu / Debian | `litearm-vr-studio-<version>_amd64.deb` | `sudo apt install ./litearm-vr-studio-<version>_amd64.deb` |
| Windows | `litearm-vr-studio-<version>-windows-amd64.exe` | 双击 |
| 其他 Linux | `litearm-vr-studio-<version>-linux-amd64` | `chmod +x` 后运行 |

`.deb` 还会装桌面入口，以及让登录用户能打开机械臂串口的 udev 规则。Linux 单文件版要求 glibc 2.35 以上（Ubuntu 22.04+、Debian 12+）。下载命令、校验、串口权限与设置存放位置见 [INSTALL_ZH.md](INSTALL_ZH.md)。

程序是自包含的：不需要装 Python，也不需要浏览器——它会打开自己的内嵌窗口。**关掉这个窗口就退出程序**（串口被释放）；刷新页面不会退出。启动时会打印实际监听的地址，默认 `http://127.0.0.1:49321/`，端口被占则顺延并打印新地址。

> [!IMPORTANT]
> **Linux 上当前用户必须能打开串口**（通常属于 `dialout` 组），否则界面能开但读不到机械臂：
> ```bash
> sudo usermod -aG dialout "$USER"   # 重新登录后生效
> ```

### 1.4 激活

本版本**只带 VR 控制台**：原来在设置页上的激活表单不在其中。请在交付前用全功能版 LiteArm Studio 完成激活，或由供方代为激活。

如果固件因未激活而拒绝使能，状态消息里会给出激活类错误。激活请求只能从全功能版（或由供方）提交，本控制台无法提交。

## 2. VR 控制台

页面分三列：左列电机负载、中列 3D 预览、右列三张卡——**遥操控制**、**VR 链路**、**臂映射**。顶栏有页面标题、只在「上位机侧在驱动机械臂」时出现的徽标，以及右上角的 **链路配置** 按钮。

### 2.1 臂映射

告诉桥哪条串口接哪条臂、夹爪在哪个 CAN 口。配反了不会报错——只是左手柄的解被发给右臂。

- 每条臂（左/右）加夹爪各一行；从列表选端口（列表不可用时可以直接输入），按 **保存到桥**。
- 卡片会标明每个值的来源：**已确认**（桥上的记录）、**安装默认**、**未上报**。
- 跟随服务实际打开的设备与上面所选不一致时，会出现不一致横幅。
- **遥操运行期间端口被冻结**——端口在启动时就写进了受管命令行。要改先停止遥操。

### 2.2 遥操控制

| 控件 | 作用 |
| :--- | :--- |
| **急停（E-STOP）** | 向跟随服务下发 `stop`，并停止转发手柄帧。紧急情况下最该按的按钮。 |
| **▶ 开始遥操** | 把机械臂串口交给桥，拉起受管的上游进程并开始转发。桥离线或头显未连接时禁用。 |
| **■ 停止遥操** | 停止转发并停止跟随服务；串口回到上位机。 |
| **在控方** | 当前谁在控制机械臂：**VR 头显**、**上位机**、**无人**、或 **两条链路**（冲突，需立刻停掉一侧）。 |

上位机侧（studio → `litearm-server:7449`）与 VR 侧**互斥**：同一批电机不能被两个控制器同时驱动。上位机侧正在执行运动、跟随、零重力拖动或阻抗模式时，开始遥操保持禁用，卡片会写明是哪一项活动占着。

安全持位或停止之后，跟随不会自己恢复：需要在头显上**松开再按一次 grip**。

### 2.3 VR 链路

整条链路的状态，数据源一行标明桥：

| 状态 | 含义 |
| :--- | :--- |
| 已连接 · 空闲 | 桥可达，没有在跟随 |
| 跟随中 | 帧正在转发给机械臂 |
| 已连接 · 持位 | 有帧到达，但机械臂在保持位置 |
| 安全持位 | 超过兜底窗口没有帧，桥已锁存持位 |

统计项：姿态帧率（Hz）、无线延迟（以窗口内最小值为基准的增量——头显时钟与控制机不可比，因此不是绝对延迟）、距上一帧时间、已转发帧数、桥转发耗时、丢弃与阻断计数。

诊断按链路顺序列出每一跳——头显、桥、IK、跟随、机械臂——各自标明「已连接 / 未连接」和属于它的实时数字。

出问题时会显示告警横幅：

- **跟随服务故障** —— 每个故障关节或标志一行（如 `J3: 5`、`FB_STALE`）；
- **跟随服务错误** —— 跟随服务自己的错误原文；
- **安全持位已触发** —— 附带触发时的断帧时长；需要松开再按 grip 才会恢复跟随；
- **兜底已关闭** —— 桥以 `FALLBACK_ENABLED=0` 运行，完全不自动持位；
- **版本不匹配** —— 桥上报的版本与本页面所写的契约版本不同，部分字段可能已被读错，需把一侧升级到一致。

### 2.4 电机负载

左臂在上、右臂在下，每个电机一条负载条，带当前值、本次会话峰值与 MOS / 线圈温度；桥上报夹爪时另加一行。某条臂不在或没有数据时分段保留位置，布局不随链路跳动。额定值来自机械臂自己的状态，显示「额定值不可用」表示固件没有上报。

### 2.5 3D 预览

由实时关节角驱动的三维视图。标题行有 **坐标轴**、**聚焦**、**俯视** 三个按钮；来源一行标明姿态是 **真机** 还是 **仿真**。

单臂时预览渲染的是支架自己的 URDF，而关节角来自 metavr 的模型；两者在关节原点、轴向与限位上不同，因此画面与 metavr 的认识不一致，机械臂看起来可能是歪的。这是已知偏差，不是数据错误。双臂时预览就是支架模型（一根立柱、两条侧装臂）。

### 2.6 链路配置

**链路配置** 按钮打开桥的可编辑设置，分组为 **整机与安装**、**跟随**、**桥服务**、**上游进程**、**安全**，以及左右臂两组：

- 整机：真机/仿真、驱动手、视图、立式/侧装、手与夹爪的启停与地址、单臂/双臂；
- 跟随：链路模式、控制律、串口、dry run；
- 各臂：串口、夹爪、host 与 port；
- 桥：日志级别、日志格式、日志文件、记录文件位置；
- 上游：是否托管进程。

每一行都会标明取值来源（`此处设置`、`config.toml`、`默认`）、是否可写，以及是**立即生效**还是**需要重启**。保存的值作为覆盖项存在桥上，对话框会显示文件路径。只读行不能编辑；桥拒绝写入时显示桥的原话，而不是笼统报错。

遥操或上游进程运行期间禁止编辑：受管命令行在启动时就固定了。要先停止遥操。

## 3. 操作流程

1. **启动桥**（控制主机），确认状态页可达；头显连 `ws://<控制主机>:8765`。
2. **启动本上位机**，它通过 zenoh 连桥（默认 `tcp/127.0.0.1:7447`，否则用 `--vr-endpoint`）。
3. **检查臂映射**：为每条臂和夹爪选好端口并保存到桥。务必在开始遥操之前完成。
4. **检查 VR 链路卡**：头显「已连接」、桥「已连接」、没有版本不匹配、没有故障横幅。
5. **按 ▶ 开始遥操**：上位机把串口交给桥并拉起上游进程。
6. **在头显上按 grip** 锚定并开始跟随；松开即持位。
7. **停止**：正常停止按 **■ 停止遥操**，紧急情况按 **急停**。停止或安全持位后，需松开再按 grip 才能恢复跟随。
8. **收工**：停止遥操后关闭窗口；串口释放、机械臂失能。

## 4. 安全规则与排障

### 4.1 安全规则

1. 开始遥操前清空工作范围，并让物理急停处在可及范围；
2. 控制台上的 **急停** 会向跟随服务下发停止并停止转发——它不是紧急情况下切断电源的替代品；
3. 上位机不在运动路径上：**关闭窗口不会停止正在运行的遥操链路**；
4. 遥操运行期间不要改臂映射或链路配置；
5. 不要让上位机侧与 VR 侧同时驱动机械臂；**在控方** 显示「两条链路」就是这种冲突。

### 4.2 排障

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| VR 链路显示桥未连接 | 桥没在跑，或本地程序的端点不对 | 启动 `litearm-vr-bridge`；桥不在本机时用 `--vr-endpoint` 启动本地程序 |
| 头显显示未连接 | 头显没连到桥的地址，或 Wi-Fi 断了 | 检查头显里的桥地址（`ws://<控制主机>:8765`）与网络 |
| 版本不匹配横幅 | 桥版本与本页面所写的契约不一致 | 把桥或本上位机升级到一致；在此之前把空字段当成可疑值，不要当成 0 |
| 开始遥操是灰的 | 桥离线、头显未连，或上位机侧正在驱动机械臂 | 看卡片横幅：它会写明是哪项活动占着。先停掉上位机侧的运动 |
| 安全持位反复触发 | 兜底窗口内没有收到帧 | 检查头显链路与 Wi-Fi；松开再按 grip 恢复跟随 |
| 显示跟随中但臂不动 | 跟随服务故障，或机械臂未使能 | 看故障横幅；在跟随侧清除故障后再按 grip |
| 启动时提示「机械臂未激活」 | 固件拒绝使能未授权机械臂 | 用全功能版 LiteArm Studio 或通过供方完成激活；本控制台无法提交激活 |
| 臂映射保存后总是回退 | 遥操运行期间改了值 | 先停止遥操，再改再保存 |
